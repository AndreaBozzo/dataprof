Try it on a small dataset

From CSV to a quality check

Use the same data as the report above. Then replace it with your own file.

1 Install the package

Python 3.11–3.15. The package has no Python dependencies.

python -m pip install dataprof

2 Get the example data

Save orders.csv in your working directory, beside your script.

3 Profile and check

Python
import dataprof as dp

report = dp.profile("orders.csv")
print(report.quality_score)
print(report["region"].null_percentage)

result = report.check(
    min_quality_score=90,
    max_null_percentage={"*": 20},
)
print(result.verdict)
report.save("report.json")

Output

93.19
25.0
fail

The score passes. The null check fails: 25% of region is missing.

The full report is saved to report.json.

Python API guide ↗
Use the same check in CI
python -m dataprof.check orders.csv --min-quality 90 --max-null "*=20"

This CSV exits with code 1. Exit codes: 0 pass, 1 fail, 2 inconclusive, 3 input, policy or output error.

1 Add the crate

In an existing Cargo project. Requires Rust 1.96 or later.

cargo add dataprof

2 Get the example data

Save orders.csv in your Cargo project directory.

3 Profile the file

Replace src/main.rs with this example, then run cargo run.

Rust · src/main.rs
use dataprof::Profiler;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let report = Profiler::new()
        .analyze_file("orders.csv")?;
    println!("Rows: {}", report.execution.rows_processed);
    if let Some(score) = report.quality_score() {
        println!("Quality: {score:.2}");
    }

    for col in &report.column_profiles {
        println!(
            "{} {:?} nulls={}",
            col.name, col.data_type, col.null_count,
        );
    }
    Ok(())
}

Output

Rows: 8
Quality: 93.19
order_id Integer nulls=0
amount Integer nulls=0
region String nulls=2

Read the data. Keep the evidence.

A report you can use in your pipeline

01

Understand each column

Inspect types, null counts, numeric summaries, patterns and distinct values. Save a report to compare it with a later run.

02

Choose your quality limits

Set a minimum score or limits on missing values. Gates return pass, fail or inconclusive when the evidence cannot settle a check.

03

See what was analyzed

Reports record the analyzed population. Uncomputed metrics stay missing, and estimates are marked so you can judge their limits.

Serialized metrics are checked across input paths and engines against a documented numeric contract.

Supported inputs

Start with the data you have

Files, in-memory tables and streams use a shared report model.

Files

CSV, JSON, JSONL and Parquet.

CSV detects comma, semicolon, pipe and tab delimiters. JSON accepts an array of objects; JSONL accepts one object per line.

Python tables and bytes

pandas and polars DataFrames, Arrow tables, batches and streams.

Also accepts dictionaries, bytes and BytesIO. Byte inputs require a format. Table libraries are optional.

Async and database sources

Async byte streams and database queries.

PostgreSQL, MySQL and SQLite need a source build with connector features. The incremental engine uses bounded accumulators.

The quality model

A score with evidence behind it

Quality analysis assesses up to seven dimensions, informed by ISO 8000-8 and ISO/IEC 25012. The aggregate uses only dimensions the data supports.

A score can pass while an individual check fails, as in the CSV above. Choose limits that fit your data.

Completeness
Missing cells and fully populated rows.
Consistency
Type consistency, format and encoding issues.
Uniqueness
Duplicate rows and key uniqueness.
Accuracy
Outliers and range violations.
Timeliness
Future dates and stale timestamps.
Validity
Conformance to detected semantic patterns.
Precision
Decimal scale in floating-point columns.
